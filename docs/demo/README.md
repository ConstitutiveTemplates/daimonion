# Demo (15 seconds)

A checkout handler logs `user_data=<email>`. The real `daimonion` CLI flags
the line, the `AGENTS.md` rules block shows why (GDPR + APPI + CCPA, via
rulebook `baseline-personal-data`), and the masked version scans clean.

![15-second demo](demo.gif)

Reproduce it without the recording:

```sh
sh docs/demo/demo.sh            # full story, ~15s of typing pauses
sh docs/demo/demo.sh --fast     # no pauses (CI / verification)
```

Re-render the GIF after changing the fixture:

```sh
vhs docs/demo/demo.tape         # run from the repo root; writes docs/demo/demo.gif
```

Files:

- `demo.gif` — the recording (VHS output, ~15s).
- `demo.tape` — the VHS script; every beat drives the real CLI on `fixture/`.
- `demo.sh` — the same beats as a plain shell script (no recorder needed).
- `fixture/` — minimal reproducible project: `app.py` (flags 1 finding),
  `app_fixed.py` (scans clean), `.daimonion.yml` (`cli` + `personal_data`),
  and `AGENTS.md` generated by `daimonion --lang ja agents-md --write`
  (real vendored rulebook snapshot, unedited).

Note: the fixture's `logger.info("user_data=%s", user.email)` needs the
`user_data` keyword to trip daimonion's
`privacy/cleartext-pii-logging-prohibited` trigger — bare
`logger.info(user.email)` does not match any builtin rule yet. The
corresponding structural gate (flag any raw identifier at a log sink) lives
in law-map as `checks/privacy/cleartext-pii-logging-prohibited.yml` (L2 with
`blocking` + `fixtures`); daimonion borrows its keyword vocabulary at L1.
